# Journeys

Generated by `pnpm test` from the headless journeys in `apps/web/test/journeys` (architecture
§10.5): each journey drives the real view-models, as the pages use them, against the real API and
auth emulator in-process, at a fixed clock. A numbered step is what the journey did (a method
call, a subscription, a clock move); the arrows list what followed, in order: requests, stream
emissions, emails. One-time codes, authenticator codes, passwords and tokens are shown as
`<…>`. Do not edit by hand.

## J1 — invitation, one-time code, first view of the calendar

`J1-invitation-first-view.journey.spec.ts`

```text
1. given the therapist adds Anna Verdi <anna@example.it>
                                                        → email to anna@example.it (invitation)
2. anna.session.restore()
3. subscribe anna.session.page$                         → anna.session.page$ emits "signIn"
4. subscribe anna.signIn.step$, busy$, error$           → anna.signIn.step$ emits "email"
                                                        → anna.signIn.busy$ emits false
                                                        → anna.signIn.error$ emits null
5. anna.signIn.requestCode("anna@example.it")           → anna.signIn.busy$ emits true
                                                        → anna.signIn.error$ emits null
                                                        → email to anna@example.it (one-time code)
                                                        → auth POST /email-otp 200
                                                        → anna.signIn.step$ emits "code"
                                                        → anna.signIn.busy$ emits false
6. anna.signIn.confirmCode(<one-time code>)             → anna.signIn.busy$ emits true
                                                        → anna.signIn.error$ emits null
                                                        → auth POST /email-otp/answer 200
                                                        → anna.session.page$ emits "client"
                                                        → anna.signIn.busy$ emits false
7. anna.signIn.dispose()                                → unsubscribe anna.signIn.step$
                                                        → unsubscribe anna.signIn.busy$
                                                        → unsubscribe anna.signIn.error$
8. subscribe anna.home.welcome$, error$                 → anna.session.accessToken$ emits <token>
                                                        → anna.home.error$ emits null
                                                        → api GET /api/v1/me 200
                                                        → anna.home.welcome$ emits "Ciao, Anna Verdi"
                                                        → unsubscribe anna.home.welcome$
9. anna.dispose()                                       → unsubscribe anna.home.error$
                                                        → unsubscribe anna.session.page$
                                                        → 0 open subscriptions
```
